 CS 320 Portfolio Artifacts: Software Testing, Automation, and Quality Assurance

 Overview

This repository contains projects I completed in CS 320 that demonstrate my skills in Java programming, software testing, test automation, and quality assurance.

- Project One: Contact Service — Includes `Contact.java`, `ContactService.java`, `ContactTest.java`, and `ContactServiceTest.java`. These files demonstrate how I developed a contact management service and used unit tests to verify that it worked correctly.
- Project Two: Summary and Reflections Report — Discusses software testing strategies, the benefits of test automation, and how testing helps ensure that software meets requirements.

 Portfolio Reflections

1. How can I ensure that my code, program, or software is functional and secure?

I can ensure that my code is functional and secure by writing unit tests, validating user input, and checking that the program meets its requirements. In CS 320, I learned the importance of testing different situations, including valid inputs, invalid inputs, and boundary conditions. For example, in Project One, I tested the contact service to make sure it could add, update, and delete contacts while preventing invalid information from being entered. I also tested situations such as duplicate contact IDs and incorrect phone numbers. These tests helped me identify potential problems and verify that the program behaved as expected. Moving forward, I will continue testing individual functions as I develop them and testing the application as a whole before considering it complete. I will also pay attention to security concerns, input validation, and error handling to help create reliable software.

 2. How do I interpret user needs and incorporate them into a program?

I interpret user needs by reviewing the requirements and identifying what the program must accomplish. I then use those requirements to guide my code and determine what needs to be tested. In Project One, the contact service had specific requirements for contact IDs, names, phone numbers, and addresses. For example, contact IDs had to be unique, names could not exceed the required character limits, and phone numbers had to contain exactly 10 digits. I used these requirements to develop the contact classes and create tests that checked whether the program accepted valid information and rejected invalid information. This experience taught me that understanding the requirements before coding is important because it helps prevent mistakes and ensures the finished program meets the user's expectations.

 3. How do I approach designing software?

My approach to designing software is to understand the problem first, break it into smaller parts, and determine how those parts should work together. I have learned that organizing code into separate classes makes programs easier to understand, test, and maintain. In Project One, the `Contact` class represented contact information and validated its fields, while the `ContactService` class handled operations such as adding, updating, and deleting contacts. Keeping these responsibilities separate made the program easier to manage and test. I also believe testing should be part of the development process rather than something done only at the end. By writing tests, reviewing the results, and correcting errors, I can improve the quality of my code. In future projects, I will continue focusing on clear design, organized code, and testing strategies that help ensure the software meets its requirements.
